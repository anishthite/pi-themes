# Ongoing and conditional distribution

## GitHub Releases

For each npm release:

1. Create the matching GitHub release and concise release notes.
2. Attach or link the catalog demo.
3. Include `pi install npm:@anishthite/pi-themes` and the GitHub repository.

## Pi package directory

Verify that the package appears in https://pi.dev/packages. The existing `pi-package` keyword and npm package are the submission; do not create a duplicate listing.

## Curated lists

Submit pull requests only to lists that explicitly accept one of: Pi packages, coding-agent extensions, terminal tools, or themes. Match each list’s contribution format and add no marketing prose.

## OpenCode and opencode.cafe

Do nothing until a tested OpenCode-compatible theme port exists. Publish the port separately, then announce it in OpenCode’s community and submit it to opencode.cafe if accepted.

## Aider, Cline, Roo Code, and OpenHands communities

Do nothing until a compatible export or integration exists. Announce the concrete compatibility, not the Pi package alone.

## Terminal-theme collections

Do nothing until themes are converted to each project’s native format. Submit individual compatible themes upstream; retain required attribution and licenses.
